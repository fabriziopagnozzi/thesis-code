\section{Pipeline Core Design}

The current implementation builds the benchmark from hidden structure before any retrieval text exists. This is the important reversal from the old MIMIC-IV-only workflow: the code first creates a controlled multi-facet retrieval problem, then renders it into clinical prose, embeds it, filters by geometry, and finally evaluates retrieval.

\begin{enumerate}[noitemsep, topsep=0pt]
	\item load a controlled ontology of conditions, subgroup labels, and two clinical axes;
	\item enumerate hidden query plans with four required answer facets;
	\item optionally calibrate which facet should be overrepresented using probe embeddings;
	\item generate structured clinical fact rows for gold facets, near-miss distractors, and background outlier clusters;
	\item render fact rows into validated clinical-style chunk documents;
	\item render deterministic natural-language queries and canonical gold answers;
	\item derive qrels directly from the hidden chunk--facet membership table;
	\item embed queries and chunks, filter queries by coverage-sensitive embedding geometry, and evaluate top-$k$, MMR, and facility-location.
\end{enumerate}

The implementation lives under:

\begin{lstlisting}[style=promptstyle]
src/experiments/medical_dataset_gen
\end{lstlisting}

The pipeline entry point is:

\begin{lstlisting}[style=promptstyle]
uv run python -m experiments.medical_dataset_gen.run_pipeline --exp <experiment>
\end{lstlisting}

The experiment configuration must already exist at:

\begin{lstlisting}[style=promptstyle]
src/experiments/medical_dataset_gen/_results/<experiment>/_config.yaml
\end{lstlisting}

The code intentionally no longer reads a source-level \field{\_config.yaml} or copies a default config. CLI flags only override selected fields of the per-experiment config. The default ontology is \field{ontology.yaml}, unless \field{generation.ontology\_path} points to a different YAML file.

The default benchmark focus is \field{retrieval.pool\_scope=query\_local}. In this setting the candidate pool for a query is the controlled local universe generated for that query: gold chunks, hard near-miss distractors, and any configured background outlier clusters. The code also supports \field{same\_condition} and \field{full\_corpus}, but the current thesis mechanism is easiest to diagnose in the query-local pool.

The implemented MVP has these constraints:

\begin{itemize}[noitemsep, topsep=0pt]
	\item each query has exactly four answer facets: two compared subgroups crossed with \field{treatment\_duration} and \field{rehab\_outcome};
	\item supported query types are \field{subgroup\_comparison} and \field{outcome\_synthesis};
	\item the ontology may contain many conditions and subgroups, but each run selects the first \field{global.conditions} conditions in ontology order;
	\item one facet is intentionally dominant, receiving \field{generation.gold\_chunks\_dominant} fact rows, while the other facets receive \field{generation.gold\_chunks\_complementary};
	\item hard distractors cycle through same-condition wrong-subgroup, same-subgroup wrong-condition, and same-axis wrong-condition patterns;
	\item optional background outlier clusters create compact but irrelevant clinical islands inside the query-local pool;
	\item chunk text can be LLM-generated, deterministic template text, or deterministic text rewritten by an LLM;
	\item queries are deterministic template renderings, with optional LLM paraphrasing guarded by entity and axis checks;
	\item gold answers are deterministic summaries of the hidden fact rows, not LLM-authored answers.
\end{itemize}

No Prolog solver, agentic retrieval, information-not-found cases, conflicting-note resolution, or LLM-as-judge qrel creation is part of the current reduced implementation. Those remain possible extensions, but they should not be described as current pipeline stages.

\subsection{Literature overview}

\subsubsection{Generic papers}
The papers start from an already existing data source and build a QA benchmark on top of it. The main ideas in the papers are: breaking down the data source into structured data supporting knowledge discovery and query generation, allowing control of query difficulty, explicit validation of synthetic data, explicit evidence provenance, and diversity checks.\\
This pipeline borrows their construction methods, but changes the starting point: MIMIC-IV is only historical context and a possible reference for terminology, condition families, comorbidity co-occurrences, demographic bins, and note style. The actual benchmark starts from a hidden schema, so that the retrieval problem has the multi-cluster structure that the raw discharge-note corpus did not reliably expose.

Useful ideas from the literature:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \textbf{Evidence-first construction.} MHTS builds questions from claims, clusters, evidence mappings, and difficulty signals \citep{lee2025mhts}. DRAGON stores explicit links among documents, queries, clues, answers, and citations \citep{shen2026dragon}. In this pipeline, those ideas become \field{query\_plans.parquet}, \field{clinical\_facts.parquet}, \field{chunk\_documents.parquet}, \field{chunk\_memberships.parquet}, and \field{qrels.parquet}. Text generation can use an LLM, but gold labels come from the hidden mapping.
	\item \textbf{Multi-aspect query structure.} ClaimSpect and MQ4CS are useful because they treat a broad user query as a set of separable aspects \citep{kargupta2025claimspect,abbasiantaeb2026multiaspect}. Here that decomposition is used before generation: a query plan explicitly chooses facets such as subgroup, treatment duration, and rehabilitation outcome.
	\item \textbf{Question-aware corpus construction.} EnterpriseRAG-Bench generates documents around planned question structures, cross-document coherence, realistic noise, completeness clusters, conflicting near-duplicates, answer facts, and conformance checks \citep{sun2026enterpriseragbench}. The current reduced implementation uses the relevant core: planned query-local clusters, intentionally redundant gold evidence, hard distractors, and embedding-geometry filtering.
	\item \textbf{On-demand hidden worlds.} PhantomWiki generates a fresh fictional universe from hidden symbolic facts, then derives templated questions and exhaustive answers with a solver \citep{gong2025phantomwiki}. Here the equivalent is a deterministic clinical world with fixed seeds, hidden fact tables, JSON logical forms, template-rendered queries, canonical answers, and qrels derived before retrieval.
	\item \textbf{Difficulty control.} MHTS motivates storing difficulty as number of facets, number of evidence pieces, and query--evidence similarity \citep{lee2025mhts}. In this benchmark, difficulty is controlled by \field{n\_facets}, dominant and complementary gold counts, distractor counts, background outlier clusters, and whether top-$k$ collapses onto the planned dominant facet.
	\item \textbf{Validation and provenance.} Rahmani et al. and RAGVAL support automatic test-collection construction but also show why validation matters \citep{rahmani2024synthetic,kenneweg2024ragval}. This pipeline therefore stores fact IDs, facet IDs, cluster IDs, membership rows, reject rows, and geometry-filter diagnostics.
	\item \textbf{Diversity.} DATAGEN uses attribute-guided generation, diversity-oriented example selection, and group checking to avoid duplicate synthetic examples \citep{huang2025datagen}. Driouich et al. use a diversity agent that clusters and samples source documents for broader RAG coverage \citep{driouich2025diverseprivate}. Those methods cannot be copied literally, because this benchmark needs both diversity and planned redundancy. The goal here is to preserve redundancy inside a dominant gold facet, enforce separation among gold facets, and create distractors that are close enough to challenge MMR.
	\item \textbf{Downstream filtering.} Kim et al. argue that synthetic generators should be judged by the downstream behavior their data induces \citep{kim2025agorabench}. For the thesis, a generated item is useful only if the candidate pool actually exposes a coverage-sensitive retrieval problem.
	\item \textbf{Optional prompt optimization.} If prompts are unstable, prompt selection can be treated as a multi-objective optimization problem. Pastri{\'a}n et al. provide one example of automatic prompt evolution through evolutionary multi-objective prompt learning \citep{pastrian2026evolutionary}. This is optional and not part of the current executable stage graph.
\end{itemize}

\subsubsection{Clinical papers and MIMIC-IV role}

MIMIC-IV can still be used as a reference for terminology, frequent conditions, comorbidity distributions, age groups, and discharge-note style, but it should not drive the current qrels. The qrels are generated from the hidden structured construction.

This can be strengthened with ideas from the medical papers for synthetic data construction:

\begin{itemize}[noitemsep, topsep=0pt]
	\item simple care-path templates that say, for a given condition and subgroup, which treatments and outcomes are plausible. This follows the same general idea as HealthBranches \citep{cosentino2025healthbranches};
	\item a small controlled vocabulary of medical terms, so the generator does not randomly alternate between inconsistent names for the same condition, treatment, or outcome. This is the practical part of knowledge-infused medical QA systems such as KI-MAG \citep{zafar2024kimag};
	\item explicit patient-group rules, such as ``encephalitis + age over 75 + rehabilitation outcome'' or ``pneumonia + diabetes + treatment duration''. This borrows the idea of decomposing clinical questions into condition, subgroup, treatment, and outcome constraints \citep{ziletti2025cohorts}.
\end{itemize}

\section{Pipeline}

\stage{Stage 1}{Ontology and Configuration}

The pipeline starts from \field{ontology.yaml} and the experiment config stored in \field{\_results/<experiment>/\_config.yaml}. The ontology has three top-level blocks:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{conditions}: display names, search terms, treatments, treatment-duration bins, and rehabilitation-outcome bins;
	\item \field{subgroups}: demographic and comorbidity labels, fields, values, and aliases;
	\item \field{clinical\_axes}: currently exactly \field{treatment\_duration} and \field{rehab\_outcome}.
\end{itemize}

The code validates the ontology with Pydantic models in \field{generation/schemas.py}. The MVP explicitly requires the two clinical axes to be exactly \field{treatment\_duration} and \field{rehab\_outcome}. A representative condition entry is:

\begin{lstlisting}[style=promptstyle]
encephalitis_myelitis:
  display: encephalitis or myelitis
  terms: [encephalitis, myelitis, neurologic deficit, acyclovir]
  treatments: [acyclovir, corticosteroids, supportive care]
  duration_treatments: [acyclovir, corticosteroids]
  duration_days:
    short: [5, 7]
    standard: [10, 14]
    prolonged: [21, 28]
  rehab_outcomes:
    home_rehab:
      - discharged home with outpatient neurorehabilitation
    inpatient_rehab:
      - transferred to inpatient rehabilitation for persistent weakness
    persistent_deficit:
      - persistent focal deficits requiring close neurologic follow-up
\end{lstlisting}

Important config fields include:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{global.n\_queries}, \field{global.conditions}, and \field{global.seed};
	\item \field{generation.query\_types}, \field{generation.dominance\_mode}, gold chunk counts, distractor counts, and background outlier settings;
	\item \field{generation.use\_llm\_chunk\_generation}, \field{generation.use\_llm\_chunk\_rewriting}, and \field{generation.use\_llm\_query\_paraphrase};
	\item embedding model and device settings under \field{embeddings};
	\item candidate-pool scope, $k$ values, $\lambda$ values, and MMR window under \field{retrieval};
	\item pass/fail thresholds under \field{geometry}.
\end{itemize}

\stage{Stage 2}{Hidden Query Plans}

\field{generation/query\_plans.py} creates \field{query\_plans.parquet}. It loads the ontology, selects the first \field{global.conditions} condition entries, enumerates every unordered subgroup pair, and emits plans round-robin over conditions so that the dataset is not filled by one condition prefix.

Each plan has two subgroups and two axes. This produces four required facets:

\begin{enumerate}[noitemsep, topsep=0pt]
	\item subgroup A + \field{treatment\_duration};
	\item subgroup A + \field{rehab\_outcome};
	\item subgroup B + \field{treatment\_duration};
	\item subgroup B + \field{rehab\_outcome}.
\end{enumerate}

The plan stores both scalar columns and JSON columns. \field{facets\_json} contains serialized \field{QueryPlanFacet} objects. \field{logical\_form\_json} contains condition, subgroup IDs, axis IDs, facet IDs, and the dominant facet ID. This is ordinary JSON, not a Prolog layer.

Example plan shape:

\begin{lstlisting}[style=promptstyle]
query_id: q00001
query_type: subgroup_comparison
template_id: subgroup_comparison
condition_id: encephalitis_myelitis
subgroup_a_id: age_over_75
subgroup_b_id: uncomplicated_diabetes
dominant_facet_id: q00001_f1
n_facets: 4
facets:
  - facet_id: q00001_f1
    subgroup_id: age_over_75
    axis: treatment_duration
    value_bin: short
    cluster_id: q00001_c1
    cluster_role: dominant_gold
    target_gold_chunks: 18
  - facet_id: q00001_f2
    subgroup_id: age_over_75
    axis: rehab_outcome
    cluster_role: complementary_gold
    target_gold_chunks: 8
\end{lstlisting}

The split assignment is deterministic from the plan index: three buckets out of twenty go to test, three to validation, and the rest to train. Query-template variants are also assigned deterministically in round-robin order within each query type.

\stage{Stage 3}{Dominance Calibration}

\field{generation/calibrate\_plans.py} creates \field{query\_plan\_calibration.parquet}. It may also rewrite \field{query\_plans.parquet}.

There are two modes:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{dominance\_mode=rotating}: keep the dominant facet assigned during plan generation and write a calibration audit table;
	\item \field{dominance\_mode=embedding\_calibrated}: render neutral query text and neutral deterministic probe chunks for each facet, embed them, and choose the facet that is naturally closest to the query.
\end{itemize}

The calibrated mode uses \field{generation.dominance\_probe\_chunks\_per\_facet} deterministic probe chunks per facet. For each facet it computes query-similarity statistics such as mean, p25, p50, and p75. The selected facet maximizes the p25-over-best-complement-p75 margin, with mean query similarity as a tie-breaker. The stage then updates:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{dominant\_facet\_id};
	\item each facet's \field{cluster\_role};
	\item each facet's \field{target\_gold\_chunks};
	\item the logical form's dominant facet field.
\end{itemize}

This stage is important because it keeps the natural query wording neutral. The dominant facet is not exposed through an artificial anchor phrase; it is chosen from the embedding geometry that the normal query already induces.

\stage{Stage 4}{Structured Clinical Facts}

\field{generation/facts.py} creates \field{clinical\_facts.parquet}. For every query plan, it expands each facet into hidden fact rows. These rows are the source of truth for later chunks, qrels, and answers.

Gold fact rows have:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{is\_gold=true};
	\item \field{facet\_id} equal to the facet they support;
	\item \field{target\_facet\_id} equal to the same facet;
	\item \field{cluster\_role} equal to \field{dominant\_gold} or \field{complementary\_gold}.
\end{itemize}

Hard distractor rows have:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{is\_gold=false};
	\item \field{facet\_id=null};
	\item \field{target\_facet\_id} set to the facet they are meant to confuse;
	\item \field{cluster\_role=hard\_distractor};
	\item \field{distractor\_type} in \field{same\_condition\_wrong\_subgroup}, \field{same\_subgroup\_wrong\_condition}, or \field{same\_axis\_wrong\_condition}.
\end{itemize}

Background outlier rows have:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{is\_gold=false};
	\item no facet or target facet;
	\item \field{cluster\_role=background\_outlier};
	\item \field{distractor\_type=background\_clinical\_cluster}.
\end{itemize}

Example fact:

\begin{lstlisting}[style=promptstyle]
fact_id: q00001_g_9_000_1234
query_id: q00001
chunk_reuse_key: <sha256>
facet_id: q00001_f3
target_facet_id: q00001_f3
cluster_id: q00001_c3
cluster_role: complementary_gold
condition_id: encephalitis_myelitis
subgroup_id: uncomplicated_diabetes
axis: treatment_duration
value_bin: prolonged
duration_days: 24
treatment: acyclovir
is_gold: true
must_mention:
  - encephalitis or myelitis
  - patients with uncomplicated diabetes
  - "24"
  - treatment duration
\end{lstlisting}

The code validates axis-specific fields. Duration facts must have \field{duration\_days} and \field{treatment}, and must not have \field{rehab\_outcome}. Rehabilitation facts must have \field{rehab\_outcome}, and must not have \field{duration\_days} or \field{treatment}.

A key implementation detail is \field{chunk\_reuse\_key}. It is derived from condition, subgroup, axis, value bin, local index, and reuse scope, but not from \field{query\_id}. Equivalent structural facts can therefore reuse the same surface chunk across queries. This is the current mechanism for controlled redundancy and generation-cache reuse.

\stage{Stage 5}{Chunk Rendering and Normalization}

\field{generation/chunks.py} creates \field{chunk\_documents.parquet}, \field{chunk\_memberships.parquet}, and \field{generation\_rejects.parquet}. The old denormalized \field{chunks.parquet} is no longer the current artifact; if it exists, the chunk stage removes it.

There are three rendering modes:

\begin{enumerate}[noitemsep, topsep=0pt]
	\item \textbf{Direct LLM generation}: \field{use\_llm\_chunk\_generation=true}. The LLM writes each chunk under strict constraints, with validation and retry feedback.
	\item \textbf{Deterministic templates}: both LLM chunk flags are false. The code renders chunk text from YAML template inventories under \field{generation/templates\_data}.
	\item \textbf{Template rewrite}: \field{use\_llm\_chunk\_generation=false} and \field{use\_llm\_chunk\_rewriting=true}. The deterministic draft is rewritten by the LLM; if rewriting fails validation, the deterministic draft is kept.
\end{enumerate}

Validation is implemented in \field{generation/chunk\_templates.py}. Hard errors reject the chunk and drop the whole query, because a kept query must have complete local evidence. Hard checks include hidden benchmark terms, leading note-section headers, missing condition evidence, missing subgroup evidence, missing treatment duration days, missing treatment name, and missing rehabilitation-outcome evidence. Soft warnings, such as a duration chunk containing rehabilitation language, are stored but do not necessarily reject the chunk.

Example rendered chunk:

\begin{lstlisting}[style=promptstyle]
The 82-year-old woman older than 75 was admitted with encephalitis or
myelitis and new gait instability. For total treatment duration, acyclovir
was continued for 21 days. Neurologic symptoms improved slowly, and the
longer course was documented because deficits persisted near discharge.
\end{lstlisting}

The stage normalizes rows into two tables:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{chunk\_documents.parquet}: one retrievable document per \field{chunk\_reuse\_key}, with \field{chunk\_id}, text, generation metadata, and clinical surface fields;
	\item \field{chunk\_memberships.parquet}: query-specific links from \field{query\_id}, \field{fact\_id}, \field{facet\_id}, \field{target\_facet\_id}, \field{cluster\_id}, \field{cluster\_role}, and \field{is\_gold} to a document \field{chunk\_id}.
\end{itemize}

This split matters. Retrieval embeds unique chunk documents, while qrels and facet coverage are query-local through the membership table.

\stage{Stage 6}{Queries and Canonical Answers}

\field{generation/queries\_answers.py} creates \field{queries.parquet} and \field{gold\_answers.parquet}. It first reads \field{generation\_rejects.parquet}; any query dropped during chunk rendering is skipped.

Query text is rendered by \field{generation/query\_templates.py} from \field{generation/templates\_data/query\_answer\_templates.yaml}. That YAML file now stores both query templates and canonical answer templates. The currently implemented query types are:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{subgroup\_comparison}: asks how treatment duration and rehabilitation outcome differ between two subgroups;
	\item \field{outcome\_synthesis}: asks for therapy-course length and discharge rehabilitation status for subgroup A versus subgroup B.
\end{itemize}

Example query:

\begin{lstlisting}[style=promptstyle]
For patients diagnosed with encephalitis or myelitis, how do treatment
duration and rehabilitation outcome differ between patients older than 75
and patients with uncomplicated diabetes?
\end{lstlisting}

If \field{generation.use\_llm\_query\_paraphrase=true}, an LLM may paraphrase the deterministic query. The paraphrase is accepted only if it still contains the condition display, both subgroup labels, and language for both axes. Otherwise the deterministic query is kept.

The canonical answer is deterministic. The code groups gold fact rows by facet, computes facet summaries, and renders the final answer through the answer-template block in the same YAML file. Duration summaries include modal value bin, average duration in days, and common treatment. Rehabilitation summaries include modal value bin and common outcome phrase.

Example answer object:

\begin{lstlisting}[style=promptstyle]
query_id: q00001
answer_text: >
  For patients older than 75, a short course, averaging 6.1 days, most
  often with acyclovir for treatment duration and an inpatient rehab
  pattern, commonly described as transferred to inpatient rehabilitation
  for persistent weakness for rehabilitation outcome. For patients with
  uncomplicated diabetes, a prolonged course, averaging 24.0 days, most
  often with acyclovir for treatment duration and a home rehab pattern,
  commonly described as discharged home with outpatient neurorehabilitation
  for rehabilitation outcome.
facet_summaries_json: {"q00001_f1": "...", "q00001_f2": "..."}
answer_facts_json: [{"facet_id": "q00001_f1", "supporting_fact_ids": [...]}]
\end{lstlisting}

\stage{Stage 7}{Qrels from Hidden Memberships}

\field{generation/qrels.py} creates \field{qrels.parquet} from \field{chunk\_memberships.parquet}. The rule is intentionally simple:

\begin{lstlisting}[style=promptstyle]
is_gold = true  -> relevance_grade = 1, support_type = positive
is_gold = false -> relevance_grade = 0
\end{lstlisting}

Non-gold chunks are further labeled as \field{hard\_negative} or \field{background\_outlier}. The qrels preserve:

\begin{lstlisting}[style=promptstyle]
query_id, chunk_id, fact_id, facet_id, target_facet_id, cluster_id,
cluster_role, is_gold, distractor_type, relevance_grade, support_type
\end{lstlisting}

This stage is fundamental to the benchmark design. Relevance is not inferred from generated prose, lexical overlap, embedding similarity, LLM judgement, or human annotation. It is projected from the hidden construction.

\stage{Stage 8}{Embeddings}

\field{retrieval/embed.py} creates embedding memmaps for unique chunk documents and queries. Chunk text is read from \field{chunk\_documents.parquet}; query text is read from \field{queries.parquet}. The implementation uses \field{helpers.embedder.Embedder}, which wraps SentenceTransformers-style document and query embedding calls.

The output files are:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{embeddings\_chunk\_vectors.npy};
	\item \field{embeddings\_query\_vectors.npy};
	\item \field{embeddings\_chunk\_ids.npy};
	\item \field{embeddings\_query\_ids.npy};
	\item \field{embeddings\_metadata.json}.
\end{itemize}

With \field{embeddings.normalize=true}, the dot product used by later stages is cosine similarity:

\begin{lstlisting}[style=promptstyle]
sim(query, chunk) = e_query dot e_chunk
\end{lstlisting}

If multiple devices are provided under \field{embeddings.devices}, the embedder uses SentenceTransformers multi-process encoding. The same embedding configuration is also used by dominance calibration.

\stage{Stage 9}{Geometry Filtering}

\field{retrieval/filter\_geometry.py} creates \field{geometry\_stats.parquet}. This stage asks whether a generated query actually exposes the intended retrieval geometry. It uses hidden labels for dataset validation, not as features exposed to retrieval methods.

For each query, the stage:

\begin{enumerate}[noitemsep, topsep=0pt]
	\item builds the configured candidate pool: \field{query\_local}, \field{same\_condition}, or \field{full\_corpus};
	\item keeps the top \field{retrieval.candidate\_pool\_n} candidates by query similarity;
	\item checks whether every hidden gold facet appears in that top-$N$ pool;
	\item checks whether nearest-neighbor top-$k$ over-selects the planned dominant facet;
	\item checks whether top-$k$ already retrieves too many distinct facets;
	\item checks whether in-facet similarity exceeds cross-facet similarity by the configured margin;
	\item checks whether enough near-miss distractors appear in the candidate pool;
	\item checks whether configured background outlier clusters are present and complete.
\end{enumerate}

The current pass condition is:

\begin{lstlisting}[style=promptstyle]
all facets present in top-N
planned_topk_dominant_count >= geometry.min_topk_dominant_count
n_topk_retrieved_facets <= geometry.max_topk_retrieved_facets
mean_in_facet_similarity - mean_cross_facet_similarity
  >= geometry.min_in_minus_cross_similarity
n_near_miss_distractors_in_pool >= geometry.min_distractors_in_pool
background outliers complete when enabled
\end{lstlisting}

The field \field{retrieval.only\_pass\_geometry} controls whether evaluation skips failed queries. The evaluation stage also checks that \field{geometry\_stats.pool\_scope} matches the current retrieval config, because changing pool scope changes the meaning of the geometry filter.

\stage{Stage 10}{Retrieval Evaluation}

\field{evaluation/evaluate.py} creates \field{evaluation\_results.parquet} and \field{evaluation\_stats.parquet}. It compares:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{top\_k}: nearest-neighbor baseline;
	\item \field{mmr}: maximal marginal relevance, a dispersion method;
	\item \field{fac\_loc}: greedy facility-location selection, the coverage method of interest.
\end{itemize}

All methods operate inside the same semantic top-$N$ candidate pool. Top-$k$ is evaluated once per configured $k$. MMR and facility-location are evaluated for each configured $\lambda$ value.

The facility-location selector uses:

\begin{lstlisting}[style=promptstyle]
score(j) = lambda * sim(q, j)
         + (1 - lambda) * marginal_coverage_gain(j)
\end{lstlisting}

The expected thesis behavior is:

\begin{itemize}[noitemsep, topsep=0pt]
	\item top-$k$ may retrieve many relevant chunks but repeatedly from the dominant facet;
	\item MMR may reduce redundancy but sometimes spends budget on semantically distant distractors;
	\item facility-location should prefer representatives of uncovered local clusters when the generated geometry is successful.
\end{itemize}

\stage{Stage 11}{Diagnostics and Plots}

The final two executable stages are diagnostic:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \field{embedding\_geometry/run.py} creates \field{embedding\_geometry\_points.parquet}, \field{embedding\_geometry\_query\_stats.parquet}, and per-query UMAP/PCA/HDBSCAN figures under \field{\_figures/embedding\_geometry};
	\item \field{evaluation/plots.py} creates evaluation figures under \field{\_figures/evaluation}.
\end{itemize}

Embedding-geometry diagnostics rebuild the candidate pool for representative queries, label candidates by hidden facet or distractor type, overlay top-$k$/MMR/facility-location selections, and compute cluster diagnostics. The automatic query selection can use a mixed set of good, mid, and bad cases, or explicit query IDs from the config.

Evaluation plots treat top-$k$ as the baseline. For MMR and facility-location, many comparison plots choose a coverage-first $\lambda^\ast$ path: maximize mean \field{FacetCoverage@k}; break ties by higher precision, lower distractor rate, and then higher \field{alpha-nDCG@k}.

\section{Data splits}

Splits are assigned deterministically from the plan index:

\begin{itemize}[noitemsep, topsep=0pt]
	\item \textbf{train}: default split for most generated plans;
	\item \textbf{validation}: used to inspect generation quality and choose retrieval hyperparameters such as MMR/facility-location $\lambda$ values;
	\item \textbf{test}: final held-out evaluation.
\end{itemize}

The current evaluation code reports over whatever queries are present after generation rejects and geometry filtering. Split-specific reporting can be added downstream if needed, because each query row keeps its \field{split}.

\begin{center}
	\begin{tabular}{@{}p{4cm}p{10.4cm}@{}}
		\toprule
		\textbf{Metric} & \textbf{Purpose} \\
		\midrule
		\field{FacetCoverage@k} & Fraction of hidden answer facets represented by at least one selected gold chunk. This is the main thesis metric. \\
		\field{MeanFacetRecall@k} & Mean per-facet recall. This is the current summary label for the raw \field{weighted\_facet\_coverage} field. \\
		\field{Precision@k} & Fraction of selected chunks that are gold for any answer facet. \\
		\field{Recall@k} & Fraction of all gold chunks retrieved, regardless of facet. Useful but secondary because the dataset intentionally contains many redundant gold chunks. \\
		\field{MAP@k} & Conventional average precision over binary gold labels. Secondary for the same reason as recall. \\
		\field{FacetMRR@k} & Mean reciprocal rank of the first selected evidence chunk for each facet. \\
		\field{alpha-nDCG@k} & Diversified ranking score using \field{facet\_id} as the subtopic label and diminishing gain for repeated facets. \\
		\field{AnswerROUGE1Recall@k} & Lexical recall between selected chunk text and the canonical answer after query-term filtering. \\
		\field{MacroFacetAnswerROUGE1Recall@k} & Average answer-overlap recall over facet-level reference summaries. \\
		\field{DistractorRate} & Fraction of selected chunks that are non-gold. Lower is better. \\
		\field{NearMissDistractorRate} & Fraction of selected chunks from facet-like hard negatives. \\
		\field{BackgroundOutlierRate} & Fraction of selected chunks from coherent non-gold background islands. \\
		\field{DominantFacetRate} & Fraction of selected chunks whose facet equals the planned dominant facet. High values indicate collapse onto the overrepresented facet. \\
		\field{RedundantGoldRate} & Fraction of selected chunks that are gold but do not add a new facet. \\
		\field{fac} & Facility-location objective score of the selected set in embedding space. Diagnostic, not a qrel metric. \\
		\field{avg\_cos} & Average query cosine similarity of selected chunks. \\
		\field{jac} & Jaccard overlap between a method's selected set and the top-$k$ selected set. \\
		\bottomrule
	\end{tabular}
\end{center}
